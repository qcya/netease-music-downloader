# 3.0.5 发布验证

范围：优化自由拖动；全屏整句保留暗字并按演唱从左向右点亮；桌面字幕继续逐字出现；移除设置页被叉遮住的文字按钮；音量已调部分显示粉色。

发布顺序：完成测试与压缩包 → 桌面保留最终 ZIP → 清理无用源码/构建缓存和旧导出，保留实际音乐与账号资料 → 提交与推送源码 → 发布带校验值的 GitHub Release。

验证不使用真实账号删除歌单，不抢占用户桌面；拖动验证采用可控鼠标位置的隐藏原生窗口，区分调用耗时与实际显示流畅度。

已验证：

- Node 292 项全部通过（包含实际 Electron 便携存储验证），Python 41 项通过。
- 隐藏原生窗口 240 次移动：旧链路约 193.70 ms、480 次完整尺寸设置、240 条布局消息；新链路约 87.06 ms、240 次双窗口批量移动、零完整尺寸设置及零重复布局消息。这是调用成本，不能解释为屏幕帧率。
- 全屏双语保留完整暗字、逐渐点亮、暂停/跳转/停顿；桌面原文和翻译逐字出现、长句单行、锁定与显示正常。
- 设置页无被叉遮挡的返回文字；音量 0%、25%、100% 同步，实际截图左侧为粉色、右侧保留灰色。
- 32 DIP 透明边缘、无额外系统外框、无 GDI 裁剪；跨显示器/DPI 边界使用完整 Electron 更新的回归通过。真实混合 DPI 桌面合成仍需目标机器验收。
- 喜欢/取消、自建歌单删除确认/取消/失败回退、取消收藏、账号切换迟到请求隔离，均使用假账号验证。

发行包仍须由 `scripts/verify_distribution.py` 核对源码、离线模型哈希、接口清单与空白用户资料，并运行 `scripts/verify_reference_package.js` 检查实际 EXE。GitHub 附件发布前核对字节数及 SHA-256；这些步骤不能用“源码测试通过”替代。
