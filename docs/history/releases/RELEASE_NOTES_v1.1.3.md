# 音乐下载器 v1.1.3

## 修复后端 ENOENT
在 Windows 上复现了 v1.1.2 的重复启动问题：第一个进程尚未退出，第二次启动同一 EXE 后，第二个便携启动器会清理两者共用的临时目录，删除后端及工作目录。
针对锁定的 electron-builder 26.0.12 配置每次启动独立解压目录；保留单实例行为，重复启动只唤回已有窗口，不删除它的资源。每次使用重新检查内置后端；独立后端使用用户数据工作目录。失效时取消“就绪”状态，显示中文原因，不提示用户安装 Python。
重试下载不再提前弹“已提交成功”；等待实际结果。

## 推荐不再在固定歌名之间循环
刷新与换一批都选择新一组。用熟悉歌名作为首次参考，从匹配歌手的分页结果和相关歌单曲目扩充候选池，保存最近展示记录并跨重启避开重复。首页显示候选池数量和已展示数量。
没有新候选时如实提示，不把旧歌换个顺序当作新推荐。保持术力口、二创、粤语、欧美电音和华语方向，不冒充私人日推或实时B站热榜。当前接口未确认完整音源的歌曲仍无播放按钮。

## 歌单不再只读十首预览
读取歌单完整曲目 ID，再分批补齐歌曲资料，按歌单顺序展示；支持返回曲目数少于请求页大小的分页接口。未取得的曲目明确计数，不虚报完整。这里只获取曲目信息，不自动下载音频。

## 验收范围
新回归覆盖237首歌单只有10首预览、分页、缺失资料、连续12批推荐去重和固定打包配置。Windows 成品必须在重复启动同一 EXE 两次后再次执行后端健康检查、独立下载、播放和歌词验收，并完整退出后重启验证锁定坐标。
真实曲库查询单独记录；受控测试不代表所有歌曲或网络都可用。保留既有音乐、歌单、歌词开关/锁定/坐标；在线播放仍不产生音频磁盘缓存。
